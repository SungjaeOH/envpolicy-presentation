# 두근두근 진실 공략전 — 발표용 게임

> <samp>글자가 이상하게 보이면 크롬 자동 번역 때문입니다. 주소창 오른쪽의 번역 아이콘을 눌러 "원본 보기"를 고르세요.</samp>

환경정책입문 C조 최종발표에서 쓰는 QR 참여 게임입니다. 발표 화면과 참가자(휴대폰) 화면이 같은 페이지에 들어 있습니다.

## 주소

- `발표자 화면` https://sungjaeoh.github.io/dgd-game/?view=host <br><samp>노트북으로 여는 화면. 발표 화면 + 아래쪽 조작 버튼. → ← 키로 장면을 넘깁니다.</samp>
- `참가자 화면` https://sungjaeoh.github.io/dgd-game/ <br><samp>휴대폰으로 여는 화면. 수업에서는 발표자 화면에 뜨는 QR로 들어옵니다.</samp>
- `발표 화면` https://sungjaeoh.github.io/dgd-game/?view=screen <br><samp>조작 버튼 없이 따라가기만 하는 화면. 빔프로젝터를 다른 컴퓨터에 연결할 때 씁니다.</samp>

## 한 Stage의 순서

1. 상황 제시
2. 1차 투표 — 선택지 3개 (배제 / 과학적 조사 / 직접 수용)
3. 1차 결과
4. 추가 자료 공개
5. 2차 투표 — 선택지 2개 (배제 / 수용)
6. 2차 결과와 점수
7. 실제 선택 공개

점수는 한 사람이 한 Stage에서 0~2점을 받습니다 (팀 문서 6-3의 표).

- 0점: 2차에서 배제
- 1점: 추가 자료를 보고 2차에서 수용
- 2점: 1차부터 직접 수용을 고르고 2차에서도 수용

2차 투표를 하지 않은 사람은 그 Stage 점수 계산에서 빠집니다. 한 사례(Stage 2개)의 반 전체 점수 ÷ 만점이 37.5% 이하면 루트 A, 62.5% 이상이면 루트 C, 그 사이면 루트 B입니다.

## 파일

- `content.js` — 화면에 나오는 글 전부. 대본은 이 파일만 고칩니다. Stage마다 `choices`가 1차 선택지, `extra`가 추가 자료, `final`이 2차 선택지입니다.
- `style.css` — 디자인. 맨 위 주석에 장면·인물·루트별로 쓸 수 있는 속성이 적혀 있습니다.
- `config.js` — 실시간 DB 주소와 설정(루트 경계, 임시 표시 등)
- `app.js` — 화면 전환, 투표, 집계, 실시간 연결
- `index.html` — 위 파일들을 불러오는 틀
- `qrcode.min.js` — QR 코드 라이브러리(손대지 않음)
- `firebase-rules.json` — Firebase 규칙 탭에 게시해 둔 내용의 사본

## 고치는 법

1. 깃허브에서 파일을 열고 오른쪽 위 연필 아이콘을 누릅니다.
2. 고친 뒤 **Commit changes**를 누릅니다.
3. 1~2분 뒤 주소에 반영됩니다. 그대로 보이면 강력 새로고침(Ctrl+Shift+R, 맥은 Cmd+Shift+R)을 합니다. 길게는 10분쯤 예전 내용이 보일 수 있습니다.

`content.js`에서 `D('...')`로 감싼 문구는 임시로 채운 것입니다. 확정되면 `D( )`를 벗기고 `'...'`만 남깁니다.

쉼표나 따옴표가 빠지면 페이지에 "content.js 몇 번째 줄 근처에 오류가 있습니다"라고 뜹니다. 그 줄을 확인하면 됩니다.

## 설정 (이미 해 둔 것)

- 깃허브 페이지: 저장소 **Settings → Pages**에서 **main** 브랜치의 **/ (root)**를 배포하도록 켜 두었습니다.
- Firebase: 프로젝트 `dgd-game`에 Realtime Database를 싱가포르(asia-southeast1)로 만들고, 규칙 탭에 `firebase-rules.json` 내용을 게시해 두었습니다.
- `config.js`의 `databaseURL`에 그 데이터베이스 주소를 넣어 두었습니다. 이 주소 하나로 연결됩니다.

`config.js`의 `databaseURL`을 비우면 데모 모드가 됩니다. 서버 없이 같은 브라우저의 탭끼리만 연결되고, 흐름을 확인하는 용도입니다.

## 발표 당일

1. 발표자 화면에서 **관리 → 새 세션으로 시작**을 누릅니다. 연습 때 자료와 섞이지 않고, 세션 이름을 모르는 사람은 응답을 읽을 수 없습니다.
2. 입장 장면의 QR로 학생들이 들어옵니다.
3. → 키로 진행합니다. 투표 장면에 들어가면 그 투표가 열리고, 다음으로 넘어가면 닫힙니다. 닫힌 1차 투표는 2차 투표 중에 고칠 수 없습니다.
4. 끝나면 **관리 → 응답 내려받기 (CSV)**를 누른 뒤 **전체 초기화**로 서버에 남은 이름·학과·응답을 지웁니다.

발표 전에 `config.js`의 `showDraftMarks`를 `false`로 바꿔 임시 표시를 끕니다.

## 알아 둘 것

- 저장소와 페이지는 누구나 볼 수 있습니다. 응답(이름·학과·투표)은 저장소가 아니라 Firebase에 저장됩니다.
- 규칙은 2026년 12월 31일까지만 읽기·쓰기를 허용합니다. 그 뒤에 쓰려면 Firebase 규칙 탭에서 시각(숫자)을 바꿔 다시 게시합니다.
- `hostKey`는 발표자 화면을 실수로 여는 것을 막는 정도입니다. 저장소가 공개라 값도 보입니다.
